Slope Training vs. Kernel Heads in Neural Surrogates: A Loss-Landscape Study

Louisiana State University • 2026

A controlled ablation of what actually makes the deep neural kernel work. Four training configurations for the UFPV source term ω̇ (inputs χ, C, Z̃″², Z̃) were compared on the same MLP backbone across five architectures and two χ ranges. The study measured off-grid generalization, training convergence and loss-landscape geometry.

17–30×
lower training loss with the kernel head vs. the Adam baseline
+14–31%
off-grid accuracy added by the kernel head at every architecture
≤ +6%
added by trainable activation slopes alone
90.8% → 14.8%
Levenberg–Marquardt accuracy (within 10%) as depth increases

Configurations. A0: Adam with fixed sigmoid slopes (baseline). A1: Adam with trainable per-neuron activation slopes. A2: A1 plus an RBF kernel regression head on the learned features (the deep neural kernel). LM: Levenberg–Marquardt as a second-order reference.

  • The kernel head wins off-grid. A2 has the best off-grid accuracy at every architecture for χ ≤ 24, at both error tolerances. It is the only first-order method that stays competitive across all architectures and both χ ranges.
  • The kernel head is the causal component. At χ ≤ 4 on the wide, shallow network it adds +62% off-grid accuracy, while trainable slopes add +4%.
  • Slopes alone can hurt. On the deep, narrow 4 × 15 network, A1 falls below the baseline (41.1% vs. 44.4% within 10%). The 2D loss contours show it stopping on a saddle point rather than a minimum. The kernel head recovers the loss (+31%).
  • Loss geometry. On wide networks all three methods converge to a convex basin. A2's basin sits about one decade below A1's and two below A0's, and its loss surface curves in every direction, while A0 and A1 have flat or symmetric directions. On narrow networks A2 develops sub-basins, since the network is too narrow to spread the kernel anchors.
  • Second-order training does not scale with depth. LM reaches 90.8% within 10% on the wide, shallow network, then drops to 40.1% and 14.8% as depth increases.

Construction-Avoiding Compression of Flamelet Tables

Louisiana State University • 2026

Building compressed UFPV tables directly from presumed-PDF convolutions, without ever constructing the full table. The number of table entries grows exponentially with the number of control variables, and each entry costs a convolution, so generating the full table is often the real bottleneck. This project evaluates only the entries a compressed representation actually needs.

  • Adaptive sparse grids. Locally adaptive hierarchical grids, one per species, refined by hierarchical surplus to a set error tolerance. Points concentrate near ignition fronts and steep gradients in progress variable instead of filling smooth regions.
  • Phase 1: compress an existing table. A proof of concept on a 29-species n-dodecane UFPV table, validated against every node of the full table, including a check that mass fractions sum to one.
  • Phase 2: build without the table. The grid queries the convolution routine directly, so building it needs only the points it requests. The full table is computed only to measure error.
  • Tensor-train cross approximation. A second route to the same goal. It samples entries chosen by the algorithm, and the number of samples scales with the tensor ranks rather than the full grid size. It is validated on source-term error and on ignition delay obtained by integrating the progress variable.
  • Why it matters. Avoiding the full tensor product makes it practical to add table dimensions, such as pressure, heat loss and more χ levels, for LES of spray and engine combustion.

Cantera Pilot: A Multi-Agent LLM Interface for Combustion Simulations

Final project, CSC 7644: Applied LLM Development • LSU • 2026

Ask a combustion question in plain English, for example "ignition delay of H₂/air at φ = 0.5, 1200 K, 10 atm", and get a computed, interpreted answer. A four-stage LLM pipeline plans the simulation, writes Cantera code, runs it in a sandbox, checks that the result is physically plausible and explains it. No knowledge of the Cantera API is needed.

3
simulation types: adiabatic flame temperature, ignition delay, laminar flame speed
4
pipeline stages: planner, code generation, execution with validation, analysis
Local
runs fully offline on an open model (Llama 3.1 8B via Ollama), with no API keys
  • Deterministic normalization. Fuel names, oxidizer shorthands, equivalence-ratio aliases and units are resolved in plain Python rather than by the LLM, including picking the right reaction mechanism for heavier fuels.
  • Retrieval-augmented code generation. Relevant Cantera documentation and hand-verified reference scripts are retrieved from a ChromaDB index and given to the code-generation agent.
  • Self-correcting execution. Generated code runs in a sandbox with an import allowlist and a timeout. If it fails, or the result violates physical plausibility bounds, the traceback or hint is fed back for up to three attempts.
  • Silent-error checks. The plausibility validators catch order-of-magnitude mistakes, such as the wrong equilibrium mode or a unit mix-up, that would otherwise look like valid answers.
  • Full audit trail. Every run saves its spec, each generated script and any errors, for debugging and evaluation.

A liquid-fueled reactor network model for enhanced NOx prediction in gas turbine combustors

Philip John, Haresh Chandrasekhar, Sourav Saha, Opeoluwa Owoyele

Liquid-fueled reactor network (LFRN) for reduced-order modeling of gas turbine combustors, adding reactors for spray breakup, droplet heating and evaporation. Validated against CFD of a liquid-fueled can combustor, it substantially reduces NOx error compared with gaseous reactor networks while keeping outlet temperatures accurate, and runs in O(10 s) on a single CPU core, over 1,000× faster than CFD.
